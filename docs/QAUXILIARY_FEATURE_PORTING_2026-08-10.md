# QAuxiliary 功能概念移植审阅（2026-08-10）

审阅来源：[cinit/QAuxiliary](https://github.com/cinit/QAuxiliary)，本地检出提交
`9b9a11a4d4c932ab69a13ab5737efc31e90ca41f`（2026-08-08）。本审阅只借鉴功能概念，
不复制 QQ/TIM 的 Hook 实现；DeepSeek 的消息模型、Compose 界面和混淆映射都需要独立适配。

## 推荐移植顺序

| 优先级 | DeepSeek 功能建议 | QAuxiliary 中的对应概念 | 适配判断 |
| --- | --- | --- | --- |
| P0 | 回复自由选择与复制 | 文本消息自由复制 | 很实用。优先让 Markdown 正文、代码块分别可选，并保留现有复制按钮；中等工作量。 |
| P0 | 复制原始 Markdown | 复制 Markdown 消息 | 适合 DeepSeek，能保留标题、表格、公式和代码围栏；需要从消息实体取原文，不能从渲染后的 Text 抄取；中等工作量。 |
| P0 | 系统朗读回复 | 文字消息转语音（系统 TTS） | 适合长回答。可放在消息长按菜单，支持开始、暂停、停止；低到中等工作量，不需要新增大型库。 |
| P0 | 链接打开方式 | 跳过内置浏览器 / 使用外部浏览器 | 适合回答中的引用链接。建议做“跟随 DeepSeek / 系统浏览器 / 每次询问”三态；低到中等工作量。 |
| P1 | 长回答完成通知 | MessagingStyle 通知 | 回答完成或后台任务结束后，在通知中显示会话名和回答摘要；需避免泄露隐私，默认关闭；中等工作量。 |
| P1 | 图片复制与系统分享 | 复制图片到剪贴板 / 聊天图片分享增强 | 适合生成图和用户上传图。长按图片增加复制、分享、保存；需要处理 `content://` 权限；中等工作量。 |
| P1 | 键盘发送行为 | Ctrl+Enter 发送消息 | 适合平板、桌面模式和物理键盘。建议允许选择 Enter 或 Ctrl+Enter 发送；低工作量。 |
| P2 | 上传图片保留原图 | 分享图片不压缩 / 自动发送原图 | 只可保证进入 DeepSeek 上传链路前不二次压缩，服务端仍可能处理；需逐版本确认上传入口；中到高工作量。 |
| P2 | 通知渠道管理快捷入口 | 通知渠道管理 | 可直接跳到 Android 的 DeepSeek 通知渠道设置，不必复刻一套管理页；低工作量，但收益一般。 |

## 已经具备，不重复移植

- 系统文件选择：聊天导入、提示词和图片选择已使用 Android 文档选择器。
- 功能搜索：模块主页已经能跨分类搜索并跳转或直接切换。
- 消息时间：已经显示消息时间并提供消息详情。
- 缓存管理：已有 DeepSeek 缓存白名单、定期清理和省电策略。
- 聊天记录导入导出：已有 Markdown 导出、可恢复备份包和按会话 ID 覆盖导入。
- 设置入口、故障日志与批量测试：已有原生设置入口、Hook 日志和一键全功能测试。

## 不建议移植

- QQ/TIM 专属的好友、群组、频道、空间、戳一戳、撤回、红包和会员功能，在 DeepSeek 中没有对应数据模型。
- 批量撤回、批量发送、篡改服务端记录等功能与当前模块定位不符，也增加数据损坏风险。
- “移除消息首尾空格”会改变提示词语义，尤其会破坏代码、Markdown 和精确格式，不应默认处理。
- QQ 界面精简类功能会改变当前 UI；目前用户要求保持现有 UI，不纳入移植。
- QAuxiliary 的 ByteBuddy、InMemoryDexClassLoader 等运行时框架不应引入。本项目已去除 DexKit并持续瘦身，移植功能应继续使用轻量、按版本显式映射的实现。

## 建议的第一批

第一批建议按“复制原始 Markdown → 系统朗读 → 链接打开方式 → 图片复制/分享”的顺序实现。
这四项不修改模块主页结构，不依赖服务端能力，国内版和 Google Play 版也能共用大部分逻辑。
