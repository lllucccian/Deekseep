## 1. 当前产品与发行策略

- 项目形态：LSPosed/Xposed 模块，包名 `com.dsmod.probe`，目标应用为 DeepSeek Chat。
- 当前主发行物：一个通用模块 APK，在运行时根据 DeepSeek 的渠道、版本号和混淆映射自动选择兼容方案。
- 当前明确支持：
  - DeepSeek 2.2.0、2.2.1、2.2.2。
  - DeepSeek 2.3.0。
  - DeepSeek 2.3.4 国内版（versionCode 245）。
  - DeepSeek 2.3.4 Google Play 版（versionCode 246）。
- 当前实机环境：Google Play 版 DeepSeek 2.3.4（versionCode 246）。
- API 102 专版、旧版独立 APK 已废弃；不要重新恢复为发布选项。
- `variants/no-local-api` 暂停维护，不作为当前交付重点。
- 当前分支按开源版本继续维护，不再启用闭源专版的加密、反调试或防篡改构建。
- 项目许可证目标为 GPL-3.0；模块本体需保留开源许可与仓库入口。

## 2. 源码与构建结构

- 核心 Hook 与功能源码：`module/src/com/dsmod/probe/`
- 模块 APK 工程：`compose-launcher/`
- 通用清单与资源：`module-universal/`
- 回归测试入口：`module/test-thinking-regression.sh`
- 通用构建脚本：`scripts/build-all.sh`
- 逆向与适配资料主要位于 `.cache/` 下，其中包含 DeepSeek 国内/GP 各版本、QQ 音乐和参考项目的分析产物。
- 当前工作树包含大量未提交修改、逆向缓存和构建产物。不要执行 `git reset --hard`、全目录清理或覆盖用户文件。

标准单线程校验与构建命令：

```sh
ANDROID_HOME=/data/data/com.termux/files/home/avf-nonprotected-poc/.termux-sdk \
  bash module/test-thinking-regression.sh

ANDROID_HOME=/data/data/com.termux/files/home/avf-nonprotected-poc/.termux-sdk \
  ./.wekit-official/gradlew -p compose-launcher :app:assembleRelease \
  --no-daemon --max-workers=1
```

APK 输出位置：

```text
compose-launcher/app/build/outputs/apk/release/app-release.apk
```

由于设备内存有限，禁止并行执行多个大型反编译、测试或 Gradle 构建任务。

## 3. 已完成并经过主要回归验证的能力

### 3.1 兼容与入口

- 通用 APK 能区分国内版与 Google Play 版 DeepSeek，并选择各自的混淆映射。
- 已有 2.2.x、2.3.0、2.3.4 国内/GP 的兼容层。
- 支持版本直接使用已知匹配方案；未知版本才进入后台自动适配流程。
- 未支持版本会显示当前版本与受支持版本范围。
- 模块设置入口、分类页面、版本页脚和彩蛋触发入口已经并入注入界面。
- 修复模块长期显示“待验证”的部分状态同步问题。

### 3.2 模块界面

- 顶级分类已整理为聊天、账号与隐私、界面美化、调试、工程等，不再保留单独的“实验性功能”总页。
- 聊天外观已作为正式功能并入界面美化。
- 原聊天外观配置为独立行；分类入口不显示冗长说明。
- 设置行支持开关、齿轮设置和一次性任务执行按钮。
- 一次性任务使用右侧执行入口和滑入式日志/结果界面。
- 每个模块子页底部显示模块版本，版本区域同时承载彩蛋触发。
- 模块 APK 本体具有首页/设置结构、系统明暗主题、设备信息、内核信息、GitHub、开源许可、赞助、配置导入与导出入口。
- 图标改用可着色矢量/Material 风格资源，处理了暗色模式黑块和不可见问题。

### 3.3 聊天外观与空间效果

- 支持自定义聊天背景、贴纸、透明度、横向/纵向取景和缩放。
- 支持贴纸一键抠图。
- 聊天气泡定制受总开关控制，关闭外观功能后不应继续生效。
- 已建立独立空间动效/视差逻辑，保留背景与前景层次配置。
- 主页欢迎鲸鱼旋转设置已加入界面美化，带齿轮和 0.1x～1.0x 速度面板。

### 3.4 Agent 与工具协议

- Agent 工具拥有统一协议、开关列表、权限模式和执行结果回传机制。
- 已有工具包括：获取时间、截图、点击屏幕、Shell、读文件、写文件、延迟执行、心跳、取消心跳、Ask User、面板/图形绘制、音乐控制等。
- 延迟执行支持毫秒级参数，并可持久化计划任务。
- Ask User 支持问题、最多四个候选答案、自定义回答以及可视化回答回发。
- 心跳支持当前会话绑定、指定时间/周期、通知、一次性任务和取消。
- 工具调用日志使用逐个调用即时显示，格式包含调用时间；设置心跳显示为 `设置心跳 to 时间`。
- 工具结果使用私有 transport 消息传给模型，目标是只进入上下文而不显示在聊天列表。
- 工具提示词已分强度档位，覆盖所有工具，而非只强化绘图工具。
- 绘图协议支持面板、进度条、线条、圆形和装饰图形等，不限定为方形面板。
- 已加强“只有收到真实工具调用并成功执行，模型才可声称已完成”的约束，降低人设聊天中的工具幻觉。

### 3.5 音乐工具

- 在线音乐路径支持搜索/播放/暂停/继续/停止等动作，并优先通过已安装的 QQ 音乐执行。
- Root 后台调起逻辑、QQ 音乐媒体会话检查和回到 DeepSeek 的处理已经加入。
- 本地音乐新增 `source=local` 与绝对文件路径参数。
- 内置最小播放器支持 MP3、AAC/M4A、OGG/Opus、WAV、FLAC、MP4/3GP、AMR、MIDI 等常见格式。
- 本地音频使用模块自己的前台媒体播放服务，不依赖 QQ 音乐。

### 3.6 本地 API

- 支持自定义地址和申请临时公网地址。
- 支持后台运行检测与 Root/Shizuku 授权后的后台运行设置尝试。
- 电池设置弹窗允许取消或点击空白区域关闭。
- 超长上下文可按输出上限裁切：存在请求上限时取有效上限，否则默认 9000 字；超出部分作为原生 TXT 附件提交，尽量保留完整内容。
- 本地 API 高级设置已经加入“超长上下文转文件”开关，默认开启。
- 专家模式文件中转已有原生附件方向的实现，目标是不把二进制文件错误转成纯文本。

### 3.7 调试、诊断与数据工具

- 支持 Hook 日志透明覆盖层，记录模块加载、请求修改、SSE、工具调用/返回及失败原因。
- 覆盖层日志统一为英文，过滤高频渲染刷屏；重启时从新会话开始，字体与透明度已降低。
- 支持崩溃日志查看和保存。
- 危险的 Native/System 级主动崩溃测试已经限制，避免再次触发系统 Freezer 连锁故障。
- 支持 Java 层可控崩溃测试。
- 支持会话统计、聊天记录备份、编辑本地对话和自定义 DeepSeek 请求调试入口。
- 本地禁言仅改变本地 UI 状态，不向服务器伪造或发送封禁数据；日期时间面板支持大跨度年份并使用自绘界面。

## 4. 当前正在执行的任务

本轮目标是修复并交付以下四项：

1. **微信赞赏码不显示**
   已定位为注入进程无法通过普通 Android drawable ID 读取模块资源。当前修复改为从 APK 内 `META-INF/com.dsmod.probe.project/sponsor_qr.png` 读取并解码，资源已确认被打包。待最终 APK 安装后实机点开确认。

2. **工具返回泄漏到可见聊天**
   已确认 DeepSeek GP 2.3.4 可见消息列表实际来自 `pq.v()`，不是旧版的 `s()`。过滤器已切到对应入口，并对 Compose SnapshotStateList 原地移除私有 EVENT/RESULT transport；文本渲染层还有空文本兜底。待用户执行真实工具调用确认既能回传模型、又不在 UI 出现。

3. **本地 API 超长上下文开关缺失**
   已在 `LocalApiAdvancedUi` 顶部添加“超长上下文转文件”开关，并接入持久化文件与实际发送逻辑，默认开启。待安装后检查入口和状态持久化。

4. **欢迎鲸鱼只改变角度、不连续旋转**
   已确认原因是 Compose Painter 绘制节点缓存，只刷新 View 不会持续调用 Painter。当前改为捕获鲸鱼资源所在的 Composer/RecomposeScope，每帧请求该作用域重组。最后一个关键修复把 Composer 注册提前到资源函数执行之前，避免错过 restart group。正在单线程回归与编译；安装后必须通过运行日志确认持续帧数，而不能只凭静态角度判断完成。

## 6. 已知风险与注意事项

- DeepSeek 使用 R8/Compose 混淆，不同渠道即使版本号相同，类名和调用链也可能完全不同；所有 Hook 必须走 `HostCompat` 或版本映射，不能把 GP 类名直接用于国内版。
- Compose UI 的“View 已刷新”不代表 Painter 会重绘。持续动画需要命中正确的重组作用域，且 Activity pause/destroy 后必须停止帧回调，避免泄漏和耗电。
- 私有工具结果必须同时满足两点：发送链路能读到，聊天可见列表不能读到。过早从底层数据源删除会导致模型收不到，过晚只隐藏文本又可能留下空白气泡。
- Root/Shizuku 并不保证第三方音乐应用允许真正的后台冷启动播放；优先使用官方 deep link、MediaSession/媒体按钮或模块内播放器，不做不稳定的进程注入。
- 主动 Native 崩溃测试曾造成 `system_server` Freezer watchdog 连锁故障，禁止恢复会发送 SIGSEGV、冻结 cgroup 或干扰系统服务的测试。
- 工作树非常脏且包含用户资产。任何清理、迁移和分支同步前都必须先列出精确目标并制作可恢复备份。

## 8. 交接判定原则

- “代码已写”不等于“功能完成”。
- “编译通过”不等于“Hook 已命中”。
- “Hook 已命中”不等于“用户路径可用”。
- 每个高风险功能至少需要：回归测试通过、APK 安装成功、目标版本 Hook 日志命中、用户路径实测四项证据。
- 无对应版本运行环境时，应明确标记为“静态兼容已实现，待对应版本实机确认”。
